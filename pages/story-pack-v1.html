Story Pack v1 Specification (Draft)

Baseline content container for playable sessions, resumable state, and explicit narrative-to-encounter transitions.

Required Sections

  • Metadata: pack identity and runtime compatibility
  • World: setting, factions, and key locations
  • Actors: player archetypes, NPCs, and enemy templates
  • State: quest variables, inventory keys, flags, progression
  • Events: triggers, conditions, outcomes, side effects
  • Encounters: battle entry conditions, scene, and turn config
  • Validation: required fields and cross-reference constraints

Design Goals

  • Every trigger is explicit and machine-verifiable
  • Runtime state is serializable and resumable
  • Narrative and combat transitions are traceable
  • Schema is additive-first for forward compatibility

Minimal Valid Pack

Source document is maintained in documents/story-pack-v1-spec.md.

Machine-readable schema is maintained in documents/story-pack-v1.schema.json, and a runnable sample pack is provided in documents/story-pack-v1.minimal.json.

Validation Quick Start

  • Top-level keys must include metadata/world/actors/state/events/encounters
  • `metadata.version` should use semantic version format (x.y.z)
  • `events.events[].trigger.type` must use a supported enum value
  • `encounters.encounters[].turnConfig.maxRounds` must be at least 1
  • After schema validation, the reference validator rejects duplicate IDs within each list (events, encounters, locations, factions, scenes, archetypes, NPCs, enemy templates)
  • Cross-references: start_encounter → encounter id, enemyWave → enemy template id, enter_location → location id; if world.scenes is non-empty, each encounter sceneId must exist in that registry

Common Invalid Cases

  • Missing `metadata.compatibility.minRuntimeVersion`
  • Using unsupported `operator` values in conditions
  • Setting `stance` outside ally/neutral/hostile
  • Using non-numeric stats in `starterStats` or `baseStats`
  • Duplicate `id` values within the same array (e.g. two events sharing one id)
  • Encounter sceneId not listed under world.scenes when that registry is present and non-empty
